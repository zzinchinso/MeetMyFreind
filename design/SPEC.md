## 3. 토큰
`tokens.json`이 단일 원본이다. 모든 토큰에 부모 결정과 근거가 있다.
`tokens.css`는 이 원본에서 생성하며, 컴포넌트 CSS에는 직접 색상·길이·기간 값을 쓰지 않는다.
미색 #FFFDFA, 상대 #FEE0E2, 내 답변 #F1ECFF. 내 답변도 어두운 #302D34 글자. 모바일 폭393/높이852, 헤더104, 입력48~120, 안전영역은 이전 규격 그대로 유지한다.
0, 100%, auto, flex/grid 배분은 구조 값으로 허용(D-12). 미디어 분기 600px은 desktop-breakpoint의 유일한 직접값(D-12).
JS의 입력 최대 높이는 CSS --entry-max에서 읽는다. OS viewport/safe-area는 기기 값이며 임의 보정하지 않는다.
서버 대기시간·사진 제한·입력 검증은 디자인 토큰이 아닌 기존 제품/전송 계약이다.

### L-01 온보딩 업데이트
서비스 워드마크와 말풍선 심볼 → 3개 핵심 메시지 수동 슬라이드 → 단일 '찐친소 풀에 등록하기' 버튼 → 주선자 목록 → 선택한 주선자와 채팅에서 성별을 말풍선 선택. 자동 회전 없음. 스와이프·좌우 버튼·페이지 점·방향키로 이동한다. 성별은 기존 여성/남성 값으로 저장하고, 양쪽 주선자 채팅에 모두 성별 선택 흐름을 둔다. 전체확인에서 성별 수정 시에는 확인 화면으로 복귀한다. 소개 페이지에는 절차/비용을 요약한 짧은 팝오버를 둔다. 기존 앱 폭/높이 토큰은 유지한다.

C-09 친구 목록(D-01·02·11): 48px 아바타 + 세로12px 여백으로 행 높이73px. 이름15px, 상태13px 한 줄 생략. 프로필 버튼은 소개 상세, 이름·상태 영역은 즉시 대화 시작. 독립 버튼으로 키보드와 터치 동작 일치. 상세는80px 아바타, 전체 소개, 목록 복귀 및 대화 시작을 제공. 모바일 외곽 치수 유지.

C-09 개정: 사용법 설명 대신 상단 대화 제목과 각 행의 메시지 아이콘으로 목적을 드러낸다. 프로필 원형 영역만 상세 버튼이고 나머지 행 전체(여백 포함)는 대화 버튼이다. 눌림·키보드 포커스 제공. 작동하지 않는 하단 탭은 제거하고 뒤로가기는 상단에 배치한다.

C-10 초대 배너(D-01·09·11): 대화 목록 위에 소개받고 싶은 사람을 편하게 이야기하라는 짧은 문구. 중립 soft 배경, 기존 두 말풍선 색상의 장식,16px 안쪽 여백과 목록까지16px 간격. 링크·버튼으로 오인시키지 않는 정적 안내. 기존 모바일 크기 및 프로필/행 클릭 계약 유지.

C-11 선택 답변(D-04·05·14): 술·흡연·종교·연봉·유입경로 모두 입력창 위 답변 버블→선택한 답을 읽기 전용 입력창에 표시→전송. 선택 전 전송 비활성, 함수에서도 빈 선택 진행 차단. 선택사항은 독립 건너뛰기 버튼만 예외. 확인·동의 단계의 독립 확인 버튼 유지.

C-11 개정: 답변 버블을 누르는 행동 자체가 전송이다. 선택 즉시 기존 검증·기록·다음 질문 흐름을 실행한다. 미선택 진행 차단과 선택사항의 명시적 건너뛰기는 유지한다.

C-07 밀도 조정(D-07·11·14): 확인 말풍선 세로 패딩8px, 항목명과 답변 간격4px. 수정 버튼은 우측 상단 독립 배치하여44px 터치 영역이 항목명 행을 늘리지 않도록 한다. 텍스트는 버튼 폭만큼 우측 공간을 확보한다.

C-09 개정(#31): 서비스 표기는 '찐친소'. 주선자 아바타는 이름 첫 글자 대신 캐릭터 이미지(assets/host-f.svg 토끼, host-m.svg 안경 쓴 곰; 온보딩 일러스트와 같은 파스텔 단색·점 눈·짧은 미소)를 목록·채팅 헤더·메시지에 공통으로 쓴다. 프로필 상세 화면은 우선 스펙에서 제외하여 목록의 아바타는 클릭 동작이 없고(app.js의 PROFILE_DETAIL=false), 나머지 행은 기존대로 즉시 대화 버튼이다. 목록 배너는 '주선을 좋아하는 두 사람이 있어요 / 편한 사람을 골라 얘기해봐요'로 선택 행동을 안내한다.

L-01 개정(#31): 소개 3슬라이드는 ① 고대생이 만든 네트워크 ② 로테이션 소개팅의 피로 없이 친구 소개처럼 ③ 피하고 싶은 사람은 피하고 프로필은 함부로 공유되지 않음. 시작은 단일 등록 버튼으로 진행하고 성별 선택은 주선자 채팅 안에서 한다. 저장 값(여성/남성)은 그대로다. 버튼 아래 보조 문구는 삭제한다.


## 이슈 #35 변경 사항 (2026-10-04)

- D-02: 채팅 헤더의 역할 별칭은 삭제하고 인물 일러스트와 이름만 표시한다. 기존 SVG 아바타 경로를 유지한다.
- C-02: 이슈에 지정된 첫 인사와 소개 동의 설명은 의미 단위 그대로 줄바꿈한다. “무조건 두 줄”보다 요청 문구의 맥락을 우선하며 320px에서도 잘림·가로 넘침 없이 표시한다.
- C-04: 입력과 플레이스홀더는 동일한 글꼴 크기, 대칭 상하 여백으로 세로 중앙 정렬한다. 여러 줄 예시는 내용 높이에 맞춰 입력창을 늘린다.
- C-05: 개인정보 동의 → 사진 없는 소개 선택 → 명시적인 등록 순서. 소개를 사전 허락 후 진행하는 선택도 동등하게 제공한다.
- C-07: 접수 후 수정은 답변·사진을 유지한 항목별 편집 화면에서 진행한다. 마지막 저장 전까지 취소 가능하다.
- C-08: 완료 화면은 무료 등록과 초대 수락은 별도 선택임을 안내한다. 진행 절차와 비용은 온보딩의 '어떻게 진행되나요?' 팝오버에서 안내한다.
- C-12: 연봉·자산은 전체 확인 전에 선택 질문으로 묻는다. 응답은 전체 확인 카드와 내 정보 수정·보기 화면에 포함하고, 다른 공유 항목과 같이 전달 표시를 한다.

## 자기 PR 질문 추가·상대 조건 질문 통합

- D-04: 6~8단계의 질문 수(3개)는 그대로 두고 구성을 바꾼다. 6단계 자기 PR(`자기소개`, 건너뛰기 가능) → 7단계 만나고 싶은 사람(`이상형`, 필수) → 8단계 상대에게 바라는 조건(`상대조건`, 필수). 이전의 `제외조건`(절대 안 되는 조건)과 `중요조건`(은근 중요한 조건) 두 질문은 `상대조건` 하나로 합친다.
- C-07: 전체 확인과 수정 화면의 해당 세 항목은 `내 매력 · 장점`, `만나고 싶은 사람`, `상대에게 바라는 조건`이다. 건너뛴 자기 PR은 `건너뛰었어`로 표시한다.
- 호환: 이전 흐름에서 작성 중이던 임시 저장(flowVersion 2 이하)은 6단계부터 다시 진행하며, 이전 두 답변은 `제외조건 / 중요조건` 형태로 `상대조건`에 옮겨 담는다. 접수된 이전 신청을 불러올 때도 같다. 시트의 `제외조건`, `중요조건` 열과 값은 그대로 둔다.
- 서버 계약: 서버가 `selfIntroduction`, `partnerCondition` 지원을 알리지 않으면 화면은 제출하지 않는다(새 답변이 저장되지 않은 채 접수되는 것을 막는다). 따라서 이 변경은 `server/Code.gs` 재배포와 함께 적용한다.
- L-03: 채팅 화면의 위아래 여백을 고정 패딩이 아니라 스크롤 내용의 일부로 두어, 키보드로 보이는 높이가 매우 작을 때(건너뛰기 칩이 있는 입력 질문 포함) 대화 영역이 0까지 줄고 입력 영역이 화면 밖으로 밀리지 않게 한다.

## 화면과 서버의 계약 점검

- 서버 필수값은 현재 화면이 항상 받는 항목만 둔다. 화면에서 뺀 `유입경로`는 필수에서 제외한다(이전에는 남아 있어 모든 신청이 거부되는 상태였다).
- `tests/contract.cjs`가 실제 `app.js`의 전체 대화를 진행해 실제 `server/Code.gs`로 제출하고, 질문한 항목이 모두 시트의 제 열에 들어가는지, 서버 필수값이 화면 수집 항목과 일치하는지 확인한다. 질문을 추가·삭제할 때 이 테스트가 먼저 실패한다.
- 새 열은 관련 열 옆에 둔다: `이메일`(연락처 옆), `초대코드`(추천인 옆), `프로필소개동의`·`프로필소개동의일시`(개인정보동의 앞), `자기소개`(종교 옆), `상대조건`(이상형 옆). 이미 만들어진 `신청` 탭에는 그 자리에 열이 끼워진다.
- 시트 열은 질문과 일대일이다. `신청` 탭의 열은 화면이 묻는 질문 26개(성별·주선자는 시작 화면과 목록에서 고르고, 사진의 답은 `사진폴더` 링크)와 서비스가 기록하는 8개(`제출시각`, `심사상태`, `사진`, `프로필소개동의일시`, `개인정보동의일시`, `수정일시`, `신청ID`, `접수토큰해시`)뿐이다. `tests/contract.cjs`가 이를 강제한다.
- 더 이상 묻지 않는 항목의 열은 만들지 않는다: `연령대`(출생연도에서 계산되던 값), `유입경로`, `제외조건`, `중요조건`. 이미 있는 탭에서는 `setup` 실행 시 `제외조건`과 `중요조건`의 값을 `제외조건 / 중요조건` 형태로 `상대조건`에 옮긴 뒤 이 열들을 지운다. `유입경로`는 다른 곳으로 옮길 수 없으므로 이전 값이 있으면 지우지 않고 setup 로그로 알린다.
- 상대에 대한 질문은 두 개다: 만나고 싶은 사람(`이상형`)과 상대에게 바라는 조건(`상대조건`).
